## Ground rules

**Production has real data.** Real member pledges are on the live deployment. It was safe to wipe freely during the build; it is not any more. Never call `resetChallenge` or `removePerson` against production without asking, and always list what is there before deleting anything. That check has already prevented one near-miss.

**No leaderboard, ever.** This is the founding constraint, from before the route existed. Names are fine — *ranking* is not. Attribution and personal recognition yes; a public wall sorted by meters no. `/pledges` has a "Most done" sort because it is a lookup tool for trainers, not the thing on the wall.

**The gym is not homogeneous.** Members in their twenties and members in their seventies. This is why pledges are self-declared rather than an even split, and why any achievement design needs at least one tier every member can actually reach. An even share would ask the same of both, which is the wrong ask in both directions.

**`logEntry` must never read the whole `entries` table.** It used to, and 35 concurrent writes produced roughly 14% `OptimisticConcurrencyControlFailure`. The running total is computed client-side from the live subscription instead, and the rate limiter is sharded for the same reason. This is the easiest thing in the codebase to undo by accident.

**Derived data goes stale silently.** `src/stateCrossings.ts` is generated by `node scripts/state-crossings.mjs`; a test recomputes it from real geometry and fails if it drifts. Re-run it after any route change. Reversing the route once already proved this is not theoretical.

**Sept 1 2026 is the start.** `CHALLENGE_WINDOW` in `src/config.ts`. `/tv` shows the pledge board before it and swaps itself to the map on the morning of the 1st, checked on a timer rather than at page load — that tab will have been open for days. Verified by faking the clock past midnight.

### Gauge bar colours

The vertical fill bar's track is `#161616` on a `#050505` background, so the **unfilled portion is nearly invisible** on the gym TV. Ideas and designs were requested before any change.

- Lives in `src/PledgePage.tsx` (search `pct}%`). Its colours are currently inline; consider hoisting them into a labelled block the way `src/MapView.tsx` does.
- The board is `h-screen` + `overflow-hidden` and sized in `vw`. **Do not reintroduce fixed px** — two separate rounds of layout bugs came from exactly that.

### Badges

Designed in conversation, not built. Two kinds, deliberately:

- **Hitting your own pledge.** Identical badge whether somebody pledged 20,000 or 300,000 — the only achievement genuinely available to every member, and the one to make loudest. The data already exists as `keptPledge` on `people:peopleWithTotals`.
- **Volume tiers on top**, roughly 25k / 50k / 100k / 250k. The average share is ~46,500.

**Open decision, not to be made unilaterally:** tier naming. Road-crew names (Navigator / Driver / Long Hauler / Road Captain) are more fun but read as a soft ranking; plain facts (100 km Club / Quarter Million) cannot. Asked, not yet answered.

## Working with this repo

- Windows and Git Bash. Files are **CRLF**; `.gitattributes` pins `.bat` to CRLF and `.sh`/`.command` to LF, and forces the executable bit on the scripts (a `.command` without it is not double-clickable on macOS, and Windows git does not track file mode by default).
- **Do not put large JS or TSX inside a bash heredoc.** It fails with "unexpected EOF". Write the file directly instead.
- **Backticks inside a double-quoted `node -e "..."` are executed by bash.** This accidentally ran two launcher scripts. Use a script file.
- If a browser preview pane is collapsed, `document.documentElement` measures **0 width** — every layout measurement is then meaningless and screenshots fail. Set an explicit viewport size before measuring.
- Verify layout by measuring section heights out of the DOM, not by eye. Several real bugs were only caught that way, and one "bug" turned out to be the measuring environment rather than the CSS.
